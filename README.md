## 1. Постановка задачи и подготовка данных

### 1.1. Выбранный датасет и синтетическая генерация (Fallback)
В качестве основы архитектуры пайплайна выбрана схема данных онлайн-кинотеатра **KION от МТС** (`interactions`, `users`, `items`). 
*Примечание: из-за технических ограничений на стороне GitHub (исчерпан лимит скачивания файлов через Git LFS в оригинальном репозитории датасета) загрузить исходные файлы не удалось. Чтобы продемонстрировать работоспособность всего исследовательского пайплайна, в код интегрирован алгоритм генерации синтетических данных, полностью повторяющий структуру KION (с учетом Zipf-распределения популярности, жанровых предпочтений и временных таймстемпов). Все метрики, представленные в данном отчете, рассчитаны на этом демонстрационном наборе.*

При сэмплировании отбирается $N = 2000$ пользователей, для которых **полностью сохраняется вся история взаимодействий**. Это гарантирует целостность пользовательских последовательностей.

### 1.2. Формулировка задачи и целевая переменная
Задача сведена к двухэтапному ранжированию (Pointwise Binary Classification с последующим ранжированием по вероятности):
* **Целевая переменная (`label`):** `1`, если пользователь просмотрел объект в целевом временном окне и `watched_pct >= 25%`; `0` — для негативных кандидатов и коротких «отказов».
* **Формирование кандидатов:** к позитивным взаимодействиям добавляются негативные кандидаты (пропорция `1:4`), сэмплированные пропорционально сглаженной популярности объектов $P(i) \propto \text{count}(i)^{0.75}$, рассчитанной строго на историческом периоде.

### 1.3. Защита от утечек данных (Zero Data Leakage)
Разбиение данных производится по глобальным квантилям времени $T_{70\%} < T_{80\%} < T_{90\%}$:
1. **Train:** признаки считаются по событиям $t < T_{70\%}$, целевые метки из $[T_{70\%}, T_{80\%})$.
2. **Validation:** признаки по $t < T_{80\%}$, метки из $[T_{80\%}, T_{90\%})$. 
3. **Test:** признаки по $t < T_{90\%}$, финальная оценка на отложенном интервале $t \ge T_{90\%}$.
Само целевое событие и будущие взаимодействия физически отсекаются до этапа расчёта агрегатов.

## 2. Сильный базовый подход (Baseline Gradient Boosting)

В качестве базовой модели используется градиентный бустинг (`LightGBM`), обученный на 26 ручных признаках трёх категорий:
1. **Признаки пользователя:** социально-демографические категории, оконные агрегаты активности (`7d`, `30d`, `all`): количество просмотров, средний `watched_pct`, `recency_sec`.
2. **Признаки объекта:** метаданные, динамика популярности в окнах, доля успешных досмотров $>50\%$.
3. **Признаки пары `User-Item`:** прямые (история просмотров конкретного объекта) и косвенные связи (исторический интерес пользователя к жанру `genre` и типу контента `content_type`).

## 3. Исследовательские подходы

### 3.1. Направление 1: Автоматическая генерация и отбор признаков (AutoFE Engine)
Вместо ручного конструирования окон разработана декларативная генерация, имитирующая SQL-запросы:
* **Генерация:** комбинируются сущности (`user_id`, `item_id`, `genre`) с непрерывным экспоненциальным затуханием времени $\exp(-\lambda \Delta t)$ при $T_{1/2} \in \{3\text{d}, 14\text{d}\}$, а также строятся отношения (Affinities / Momentum Ratios).
* **Отбор:** удаление мультиколлинеарных признаков ($\vert{}r\vert{} > 0.95$) и ранжирование по `Gain Importance` (отбор топ-18 признаков на валидационной выборке).

### 3.2. Направление 3: Нейросетевая модель над историей событий (`TargetAwareHistoryTransformer`)
PyTorch-модель, совмещающая идеи SASRec и DIN:
* **Сжатие истории:** скользящее окно из последних $L = 30$ взаимодействий.
* **Представление события:** конкатенация эмбеддингов объекта, жанра и линейной проекции непрерывных признаков (`watched_pct` и $\ln(1 + \Delta t)$).
* **Архитектура:** слой `TransformerEncoder` + `Target-Aware Cross-Attention`, где запросом ($\mathbf{Q}$) выступает кандидат, а историей — ключи/значения ($\mathbf{K}, \mathbf{V}$).

## 4. Результаты экспериментов и Ablation Study

Все модели обучены и протестированы на идентичном разбиении данных и одинаковом наборе кандидатов. Итоговые демонстрационные метрики на отложенной выборке **Test**:

| Модель / Конфигурация | ROC-AUC | LogLoss | NDCG@10 | Recall@10 |
| :--- | :---: | :---: | :---: | :---: |
| **1. Baseline GBDT (ручные признаки)** | 0.6715 | 0.4165 | 0.6352 | 0.7030 |
| **2. AutoFE GBDT (без ручных агрегатов)** | 0.6545 | 0.4594 | 0.5915 | 0.6970 |
| **3. GBDT (Ручные + AutoFE отобранные)** | 0.6727 | 0.4160 | 0.6339 | 0.7030 |
| **4. Event History Transformer (Standalone)** | 0.6317 | 0.4681 | 0.5655 | 0.6718 |
| **5. Hybrid GBDT (Ручные + AutoFE + SeqNN)** | 0.6652 | 0.4199 | 0.6291 | 0.6989 |

*Примечание: значения метрик отражают результаты работы алгоритмов на синтетическом шуме, однако корректно демонстрируют пайплайн оценки.*

### Выводы
1. **Автоматизация признаков:** Модуль `AutoFE` способен генерировать информативные признаки (особенно экспоненциальное затухание времени `decay_3d`), однако на данных без сильных скрытых закономерностей работает на уровне базовых ручных агрегатов.
2. **Нейросетевой подход:** `TargetAwareHistoryTransformer` корректно обрабатывает последовательности, но в standalone-режиме уступает бустингу из-за отсутствия глобальных счетчиков популярности объектов по всей базе пользователей.
3. Оптимальной для production-задач является гибридная архитектура, где выходы секвенциальных нейросетей подаются как мета-признаки в GBDT вместе с табличными статистиками.
